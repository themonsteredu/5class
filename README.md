# MOAKIT 5class · 삼국시대 탐구실

초등 5학년 AI·사회 융합 10차시 웹교재. 사용자 제공 AI-L.E.A.P 교육과정 10차시에 맞추고, culture_bosung의 수업 교재 / 학생 활동 / 교사 자료 분리와 단계별 큰 화면 방식을 참고했습니다.

## 실행

Node 20 이상, 외부 패키지 의존성 없음.

```sh
npm run dev   # localhost:5175
npm test
npm run build # dist 정적 파일
```

Vercel 설정은 `vercel.json`에 포함되어 있습니다. 배포는 정적 호스팅이며 서버 비밀키가 필요하지 않습니다.

## 구성

- `#home`: 10차시 목차
- `#lesson/1` ~ `#lesson/10`: 각 6화면, 총 60개 교재 화면 / 해설 공개 / 큰 글씨 / 전체화면
- `#activity/1` ~ `#activity/10`: 관찰 → 질문 → 조사표 → 분류 → 관계도 → 낱말 분석 → 전시 설계 → 해설 작성 → 상호 검증 → 발표·성찰
- `#library`: 비상 사회 5-2 교과서 연계 자료 15종 / 나라·생활 주제 필터 / 두 자료 비교 / 추가 탐구 4종
- `#museum`: 모둠 전시 관람과 HTML 다운로드 (보유한 사진·글꼴 포함, 교과서 사진은 온라인 원문 링크)
- `#teacher`: 40분 운영 흐름, 차시별 지도안, 10종 A4 활동지와 관찰 기준

## 저장과 공유

현재 기기의 localStorage (`moakit-5class-v1`)에 저장합니다. 다른 기기는 JSON 내보내기/가져오기로 이어서 작업합니다. 가져오기는 현재 기록을 교체하므로 확인 창이 표시됩니다. 학생 글은 화면과 관람용 HTML에서 이스케이프하고 출처 주소는 HTTPS만 허용합니다. 파일 크기·스키마·자료 수·참조를 검증합니다.

관람 HTML에 포함된 교과서 원문 사진 링크는 인터넷 연결이 필요합니다. 관람 HTML에는 최종 해설·자료 출처·관계도·낱말 해석만 포함합니다. 확인 전 AI 초안, 성찰, 피드백 등 비공개 작업 기록은 포함하지 않습니다. 해설을 수정하면 해당 자료의 확인 표시가 해제됩니다.

실시간 학급 공유, 학생 계정, 허브 로그인 연동, AI API 자동 생성/분류는 구현 범위에 없습니다. 2·4·8차시는 교사 관리 AI의 실제 결과를 기록합니다. 낱말 분석은 사용자가 지정한 문자열의 중복 없는 등장 횟수이며 형태소 분석 또는 AI 분석으로 표시하지 않습니다.

## 자료

사용자 기존 ai-history-ar 프로젝트의 실제 사진을 재사용했습니다. 역사 설명 출처와 사진 출처는 개별 표시합니다. 선택한 자료의 수량으로 삼국 전체의 유산 분포를 추론할 수 없습니다. 출처 사이트 연결은 기관 운영 상황에 따라 달라질 수 있으므로 교사 자료에서 사전 확인을 안내합니다.

사진별 저작자·라이선스는 `ASSETS.md`와 `data.js`를 참고하세요. 학생에게 보이는 사진은 원본 비율을 유지합니다.

## 1차시 관찰 수업
1차시는 여섯 자료 살펴보기(6분) → 생활의 단서 찾기(8분) → 사진으로 모르는 것 함께 생각하기(7분) → 모둠 질문(8분) → 알아볼 방법(7분) → 질문 나누기(4분)로 이어집니다. 수산리 벽화, 백제 식기, 가야 집 모양 토기, 신라 토우, 가야 갑옷·투구, 미륵사지 석탑 복원 모습의 교과서 발췌 이미지를 제공합니다. 금관·무령왕릉은 1차시에 포함하지 않습니다.

관찰·질문·조사 방법 화면 위에서 여섯 유물을 바로 바꿔 볼 수 있습니다. 함께 연습하는 화면도 선택한 유물에 맞춰 본 것 → 사진으로 모르는 것 → 더 알아볼 질문을 단계적으로 공개합니다. 유물을 바꾸어도 현재 활동 단계는 유지합니다. 알아볼 방법으로 교과서·박물관 설명·AI의 도움을 연결하고, AI는 찾아볼 낱말이나 쉬운 설명을 제안할 수 있을지 예상합니다.

기록은 A4 한 장의 종이 활동지에만 남깁니다: 본 것 두 가지, 모둠 질문 하나, 알아볼 방법 하나. 선택한 유물은 이 기기에 저장되며, 마지막의 ‘이 유물로 2차시 이어가기’로 같은 유물을 연결합니다. 학생 답안은 종이에 기록합니다. 이전 디지털 관찰 기록은 프로젝트 JSON과 기록 인쇄에서 유지합니다. 새 활동지는 다음 차시까지 보관합니다.

실시간 AI 호출은 없습니다. 2차시는 학생이 만든 질문을 조사한 뒤 준비된 학습용 문장도 검증합니다. 다른 차시의 일부 자료는 교과서 원문 링크를 사용합니다. 이미지 출처와 발췌 범위는 ASSETS.md에 기록했습니다.

1차시 활동지: `assets/worksheets/lesson-1.pdf` (A4, 1쪽). 수정 후 `python scripts/worksheet-lesson1.py`로 다시 생성할 수 있습니다. 생성에 PyMuPDF와 fontTools가 필요하며, 사이트 실행·빌드에는 필요하지 않습니다. 교재와 활동지는 같은 S-Core Dream 글꼴을 사용합니다.

## 2차시: 우리 질문 조사와 유물 설명 검증
1차시 질문 이어가기(5분) → 우리 질문 조사(12분) → 추가 문장 살피기(4분) → 문장 검증(12분) → 함께 정리(4분) → 조사 나누기(3분). 학생이 만든 질문을 먼저 조사하고, 같은 유물에 대한 학습용 문장 3개를 추가로 검증합니다. 실시간 AI 호출은 없습니다.

유물별 A4 활동지는 2쪽입니다. 1쪽에는 1차시의 질문, 확인한 자료와 근거, 알게 된 답, 더 알아볼 점을 기록합니다. 2쪽에는 추가 문장의 처음 생각·출처·근거·최종 판단·수정 문장을 기록합니다. `assets/worksheets/lesson-2.pdf`는 6종 묶음(12쪽)이며 선택 유물별 PDF도 제공합니다. `#lesson/2`와 `#activity/2`는 같은 교재를 엽니다. 교사용 해설은 헤더와 마지막 단계에서 엽니다.

활동지 재생성: `python scripts/worksheet-lesson2.py`. PyMuPDF와 fontTools가 필요합니다. 공식 기관 첫 화면 링크에는 검색어를 함께 안내합니다. 질문의 답을 일부만 찾았다면 남은 궁금증을 3차시로 이어 갑니다.

## 3차시: 우리 반 문장판
수업코드(숫자 4~12자리)와 모둠(1~6)으로 입장합니다. 모둠은 2차시에 검증한 문장 3개를 올린 뒤, 새로 맡은 교과서 유물의 확인할 문장 3개(사실·거짓·판단하기 어려움 각 1개)를 판단해 올립니다. 고친 문장은 원래 문장과 함께 저장하며 문장판에 줄 그어 보여 줍니다. 선생님 화면은 모든 모둠 문장을 한 화면에 맞춰 보여 줍니다.

- 새 유물 문장: `lesson-three-data.js` / 교사용 정답: 3차시 화면의 `교사용 정답·근거`
- 활동지: `assets/worksheets/lesson-3.pdf`(8쪽)와 유물별 PDF. 재생성: `python scripts/worksheet-lesson3.py` (PyMuPDF, fontTools, Node 필요)

## 4차시: 우리 기준으로 나누고 모둠 로봇 만들기
3차시와 같은 수업코드로 입장합니다. ① 모둠이 기준과 묶음 이름을 직접 정해 3차시 문장판의 유물 카드를 나누고 저장합니다. ② 모둠마다 로봇이 하나씩 있고(예: 2모둠 신라 로봇), 그 모둠이 3차시에 조사한 유물만 설명합니다. 3차시에 올린 문장을 골라 가르치거나 직접 문장을 가르칩니다. ③ 모둠 로봇에게 말(크롬 음성 인식)이나 글로 묻습니다. 배운 문장과의 같은 말을 찾아 문장 상태대로 `맞아요 / 아니에요 / 알 수 없어요 / 몰라요`로 답하고, 모르는 유물은 그 유물을 아는 모둠 로봇을 알려 줍니다(`robot.js`, 규칙 기반). 대답은 기기 음성으로 읽어 줍니다. ④ 모둠 로봇이 배운 문장을 한눈에 정리하고, 교사가 제미나이에게 맞는지 확인을 받습니다(아래 ‘4차시 제미나이로 확인하기’). 교사 화면에는 기준 예시와 함정 문장 넣기가 있습니다.

## 4차시 제미나이로 확인하기
4번째 화면에서 모둠 로봇이 배운 문장을 한눈에 정리하고, 제미나이에게 보낼 요청문을 역할 → 할 일 → 답하는 방법 → 자료 순서로 보여 줍니다. 선생님 화면과 학생 태블릿 모두 `✨ 제미나이에게 확인 받기`(문장마다 맞아요 / 고쳐야 해요 / 자료로는 알 수 없어요 판정)와 `두 로봇에게 묻기`(우리 규칙 로봇과 제미나이 로봇 비교)를 쓸 수 있습니다.

- **기본은 무료 제미나이 앱 방식**입니다. Vercel에 `GEMINI_API_KEY`가 없으면 화면에 `📋 요청문 복사하고 제미나이 열기` 단추가 나와, 요청문을 복사하고 gemini.google.com을 새 창으로 엽니다(선생님 화면·학생 태블릿 모두). 아이들은 붙여 넣어 묻고, 제미나이 판정을 활동지에 적습니다. ‘두 로봇에게 묻기’도 우리 로봇은 바로 대답하고, 제미나이 로봇은 질문이 든 요청문을 복사해 앱에서 묻습니다.
- 아래 키·비밀번호 설정은 사이트 안에서 제미나이 대답을 바로 받고 싶을 때만 필요합니다. 키가 있으면 단추가 자동으로 바뀝니다.
- 선생님 화면의 `🖨 모둠별 활동지 인쇄`는 로봇마다 한 장짜리 활동지(가르친 문장 표 · 내 예상 · 제미나이 판정 · 자료로 확인 · 요청문 · 알게 된 점)를 만듭니다. 문장 번호는 TV의 제미나이 판정 번호와 같고, 확인을 마친 뒤에는 제미나이 판정을 채워서 인쇄할 수도 있습니다.
- 요청문은 `gemini-prompt.js` 한 곳에서 만들고, 화면과 서버(`api/gemini.js`, Vercel 함수 `/api/gemini`)가 같은 파일을 씁니다. 서버는 브라우저가 보낸 문장으로 요청문을 다시 만들기 때문에 아무 글이나 제미나이에게 보낼 수 없습니다.
- Vercel 프로젝트 환경 변수에 제미나이 API 키 `GEMINI_API_KEY`와 선생님 비밀번호 `TEACHER_PIN`을 넣고 다시 배포(Redeploy)합니다. 키는 브라우저에 보내지 않습니다. 비밀번호가 맞아야만 서버가 제미나이를 부르므로, 학생 태블릿이 ‘선생님 화면’으로 들어와도 제미나이를 쓸 수 없습니다(선생님 기기와 학생 태블릿마다 처음 한 번만 선생님이 입력). 비밀번호를 30번 틀리면 그 인터넷 주소는 10분 동안 막힙니다.
- 설정이 빠져 있으면 선생님 화면이 무엇이 없는지 알려 주고 제미나이 버튼을 끕니다. 그때도 `요청문 복사` → `제미나이 앱 열기`로 직접 붙여 넣어 쓸 수 있습니다.
- 무료 사용량이 찬 모델은 건너뛰고 다음 모델에게 묻습니다. 모두 차면 ‘잠시 뒤 다시’ 안내가 나옵니다. 결제 정보를 등록하지 않은 무료 키는 요금이 나가지 않습니다.
- 기본 모델은 `gemini-3.5-flash-lite`이고, 없어진 모델이면 `gemini-3.1-flash-lite`, `gemini-3.8-flash` 순서로 넘어갑니다. 환경 변수 `GEMINI_MODEL`로 맨 앞 모델을 바꿀 수 있습니다.
- 학생 이름은 보내지 않습니다. 무료 사용량에서는 Google이 요청 내용을 서비스 개선에 쓸 수 있습니다.
- 로컬에서는 `GEMINI_API_KEY=... TEACHER_PIN=... npm run dev`로 같은 함수를 실행합니다.
- Gemini API 약관은 18세 이상만 쓸 수 있고, 18세 미만이 쓸 가능성이 높은 서비스에서의 사용을 막고 있습니다. 그래서 제미나이 호출은 선생님 비밀번호로만 열리게 했습니다. 학교·교육청 AI 사용 지침을 함께 확인합니다.

## 5차시: 우리 모둠 로봇 완성하기
3·4차시와 같은 수업코드로 입장합니다(`lesson-five.js`). ① 4차시 모둠 로봇에게 이름·성격·말버릇·자기소개·대표 유물을 정합니다. ② 교과서와 자료에서 찾은 새 문장을 **출처와 함께** 더 가르칩니다(4차시 로봇 문장에 `5차시` 표시). 선생님은 4차시 ‘제미나이로 확인하기’ 화면으로 바로 갈 수 있습니다. ③ 선생님 화면에서 인쇄한 **로봇 설계도**의 네모 안에 그린 그림을 태블릿으로 찍어 올리고, 크기·위치·방향을 맞춘 뒤 배경색과 근거 스티커(부분 ← 유물, 근거)로 로봇 카드를 저장합니다. ④ 로봇 발표회: TV에 6모둠 로봇 카드가 함께 뜨고, 카드를 눌러 질문하면 로봇이 정한 말버릇과 성격별 목소리로 대답합니다.

- 로봇 이름·나라·담당 유물·문장의 주인 규칙은 `robot-room.js` 한 곳에서 4·5차시가 함께 씁니다.
- 프로필(`P`)과 디자인(`D`)은 4차시 방(`r<수업코드>`)에 모둠마다 마지막 저장만 씁니다. 새 서비스 없이 저장하기 위해, 로봇 그림은 384×384로 줄인 WebP/JPEG를 글자(base64)로 바꿔 그림마다 새로 만든 방(`p` + 11자)에 700자씩 나눠 저장합니다(`lesson-five-store.js`). 디자인 줄에는 그 방 이름만 남깁니다.
- 저장 함수 규칙상 한 모둠은 한 방에 40줄까지라, 화면에 남은 줄 수를 보여 줍니다.

## 공유 저장
3·4차시 기록은 Supabase `class5` 스키마에 저장합니다. 브라우저는 공개 키로 `class5_*` 함수만 호출하며 표에 직접 접근할 수 없습니다. 학생 이름은 받지 않고 모둠 번호만 저장합니다. 3차시 문장은 같은 모둠이면 어느 태블릿에서든 지울 수 있습니다(`class5_remove_group`, `supabase/class5_remove_group.sql`, 함수가 없으면 올린 태블릿에서만 지움).

4차시 기록(모둠 분류 `S`, 로봇이 배운 문장 `R|나라|유물|t`, 모둠 칸 = 로봇)은 3차시와 같은 `class5_add/list/remove` 함수로, 수업코드 앞에 `r`을 붙인 별도 방에 저장합니다(`lesson-four-store.js`). 3차시 문장판에는 섞이지 않습니다. 전용 표로 옮길 때 쓸 구조는 `supabase/class5_lesson4.sql`에 있습니다(아직 적용하지 않음).
